# v0.2.0 — Make it adoptable + rich text
Date: TBD · Status: **in development**

## Summary (planned)
Turn Verbaly from "core published" into "actually usable end-to-end": publish the compiler + Vite plugin, and add rich-text translation (`<Trans>`) to the framework adapters.

## Planned scope
- **Publish `@verbaly/compiler` + `@verbaly/vite`** (first publish, at their current 0.1.0 — matches core). Requires the `@verbaly` org on npm. Codeless; unblocks the whole zero-config flow for real users.
- **`<Trans>` rich-text** in `@verbaly/react` + `@verbaly/vue` — interpolate elements/links inside a translated sentence.
- **npm README** for the `verbaly` core package ships with this release (already prepared at `packages/core/README.md`).
- **(maybe) `verbaly.config.ts`** — typed config file.

## Design decisions (resolved)
- **`<Trans>` model:** runtime-first — lives entirely in the adapters, no compiler change. It calls the context `t(id, values)`; since the message parser ignores `<`/`>`, the formatted string keeps the tags, which the adapter then interpolates. Compiler write-in-place extraction is a fast-follow.
- **`<Trans>` tag syntax:** named — `Read the <terms>terms</terms>` + `components`.
- **ICU escape hatch:** deferred to 0.3.0 (needs zero-dep-vs-dep design).

## Per package

### @verbaly/react ✅ — `<Trans>` (8 tests)
- `<Trans id values components />`: `components` is `Record<string, ReactElement>`; named tags are wrapped via `cloneElement`. Nesting supported; unknown tags degrade to inner text. Re-renders on locale change (via `useT`). No JSX in src (`createElement`/`cloneElement`).

### @verbaly/vue ✅ — `<Trans>` (10 tests)
- `Trans` component; `components` is `Record<string, (children) => VNodeChild>` (idiomatic Vue render functions). Same parser/behavior as React. Reactive via `trackVersion`.

### verbaly (core) / @verbaly/compiler / @verbaly/vite
- No code change. compiler + vite still pending first publish (need `@verbaly` org).
