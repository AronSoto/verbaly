# v0.6.0 — The compiler understands your whole codebase

Date: 2026-07-04 · Status: **ready to publish** (versions aligned at 0.6.0)

## Summary

The two compiler gaps close: JSX `<Trans>` children are now extracted write-in-place (like `` t`...` `` always was), and `verbaly.config.ts` works. Rich text in React stops being runtime-first. No breaking changes.

## Per package

### @verbaly/compiler — +17 tests (55 total)

- **Added: JSX `<Trans>` extraction (write-in-place).** Write the source text inline — `<Trans>Read the <a href="/terms">terms</a>, {name}</Trans>` — and the compiler extracts the message (`Read the <a>terms</a>, {name}`), generates the stable key, syncs catalogs/types, and rewrites the element to `<Trans id="…" values={{ name }} components={{ "a": <a href="/terms" /> }} />`.
  - Child element **attributes are preserved** in `components` (self-closed source slice); component tags are lowercased (`<Break/>` → `<break/>`); colliding tag names get suffixes (`a`, `a2`).
  - Params follow the same naming as tagged templates (`{user.name}` → `{name}`, dedupe, positional `_i` for complex expressions).
  - **Whitespace is React-faithful**: extraction produces exactly what React renders (a line break between an element and text yields no space — the `{' '}` idiom works). Tested against Babel's JSX text semantics.
  - **Bails safely** (element left untouched) on: existing props, fragments/spread children, member-expression tags, nested `<Trans>`, tagged templates inside children. Runtime-first `<Trans id>` keeps working unchanged.
- **Fixed: `<Trans id="x">` now counts as a used key.** Before, `check` flagged those catalog entries as unknown and `--prune` deleted them.
- **Added: `verbaly.config.ts` / `.mts`** via `bundle-require` (lazy-loaded). `esbuild` is an **optional peerDependency** — a clear error tells you to install it if missing. Precedence: `js`/`mjs` → `ts`/`mts` → `json`.

### verbaly · @verbaly/vite · @verbaly/react · @verbaly/vue

- No code changes. The Vite plugin picks the feature up for free (same `analyze`/`transform`/`loadConfig` path, `.jsx/.tsx` already watched). Version-aligned release.

## Breaking changes

- None. Extraction only triggers on `<Trans>` **without props**; every existing usage is untouched.

## New API / signatures

- `Analysis`/`TaggedMessage.jsx?: { name, components }` + `type TransComponent` (compiler exports).
- `verbaly.config.ts` support in `loadConfigFile` (CLI + Vite inherit it).
- New compiler deps: `bundle-require` (dependency), `esbuild >=0.18` (optional peer).

## Notes

- Vue SFC templates are not JSX — extraction applies to `.jsx/.tsx` only; Vue `<Trans>` stays runtime-first (documented).
- Component tag names come from the source element name; the message stores lowercase named tags, matching `parseTags`.
