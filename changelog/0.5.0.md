# v0.5.0 — Hardening + performance, with receipts

Date: 2026-07-04 · Status: **published** (all 5 packages on npm, aligned at 0.5.0)

## Summary

Defensibility audit of the 0.4.0 codebase: every finding fixed, plus published benchmarks that back the project pillars (fast, light, simple-but-robust). No breaking changes, no new user-facing API.

## Audit findings → fixes

### verbaly (core) — +2 tests (80 total)

- **Perf: fallback chain memoized.** `chain()` (BCP-47 narrowing + fallbacks) was recomputed and re-allocated on **every `t()` call**; now cached and invalidated on `setLocale`. Biggest hot-path win.
- **Perf: DOM args cached per element.** `bindDom` re-ran `JSON.parse` on `data-verbaly-args` for every element on every re-render (locale switch = whole page); now a per-binder `WeakMap` keyed by element with raw-string comparison — attribute edits still re-parse (observer test covers it).
- **Robustness: AST cache capped** at 2000 entries (cleared and rebuilt beyond that). Catalog messages are bounded, but dynamic/CMS messages via `addMessages` could grow it without limit.
- **Robustness: `resolveLocale` narrows stored values.** A persisted `es-PE` with `supported: ['es']` was silently ignored; now the same exact→base matching applies to storage and navigator.

### @verbaly/vite

- **Fixed: stale self-write entries swallowed external edits.** The watcher dedupe skipped reloads whenever a `selfWrites` entry existed, without comparing content — if the FS skipped an event (e.g. identical write), the _next real user edit_ to that catalog was ignored until restart. Now the entry is checked against the file on disk; `add` events for new catalog files go through the same path.

### @verbaly/compiler · @verbaly/react · @verbaly/vue

- No changes (audited: adapters clean — `useSyncExternalStore`/`onScopeDispose` correct, `setLocale` safe unbound). Version-aligned release.
