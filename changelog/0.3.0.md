# v0.3.0 — ICU escape-hatch + robustness

Date: 2026-07-03 · Status: **published** (all 5 packages on npm, aligned at 0.3.0)

## Summary

Opt-in ICU MessageFormat support (zero-dep) plus robustness fixes surfaced by a full codebase analysis. No breaking changes.

## Per package

### verbaly (core) — +14 tests (57 total)

- **Added: ICU escape-hatch.** A message with an ICU argument (`{count, plural, one {#} other {#}}`, `select`, `selectordinal`, `{n, number/date/time, style}`) is auto-detected and parsed into the **same `MessageNode` AST** as the native format — so the formatter is unchanged. Recursive-descent parser in `icu.ts`, **zero dependencies**. Supports `#`, `=N` exact, nested, and ICU `'…'` apostrophe quoting. `selectordinal` uses real ordinal plural rules (new `ordinal` flag on `ParamNode`; `pluralRules(locale, 'ordinal')`).
- **Added: `parseTags` + `TagNode` export** — the named-tag tokenizer that powers `<Trans>`, now shared and hardened (unclosed tags keep their inner content; stray closes render literal). 6 new tests.

### @verbaly/react · @verbaly/vue

- `<Trans>` now uses the core `parseTags` tokenizer instead of a per-package regex walker — **dedupes ~30 duplicated lines** and hardens malformed-input handling in one place. Behavior unchanged for well-formed messages.

### @verbaly/compiler

- **Fixed:** key-collision detection. When two different source texts hash to the same key, the registry now **warns** (build-time) instead of silently dropping one (`registry.ts`).

### @verbaly/vite

- **Fixed:** `MessageRegistry.remove` is wired to the dev watcher's `unlink` — deleting a source file no longer leaves ghost keys until restart.
- Bumped dev `vite` 8.1.2 → 8.1.3.

## Breaking changes

- None.

## New API / signatures

- `parseTags(text): TagNode[]` and `type TagNode` (core exports).
- `ParamNode.ordinal?: boolean` (internal AST; used by ICU selectordinal).
- ICU is opt-in by syntax — no new call-site API; write ICU in a message and it just works.

## Docs impact (for verbaly-web)

- **`docs/format` page:** add an "ICU escape-hatch" section (when/why + examples: plural/select/selectordinal). Note it's opt-in and zero-dep.
- **`/changelog`:** add the 0.3.0 entry.
- No change to `<Trans>` docs (behavior identical).

## Notes

- A runtime `console.warn` for NaN/Invalid-Date values was prototyped and **dropped** to keep the core lean (invalid output is self-evident; the build-time collision warn stays).
